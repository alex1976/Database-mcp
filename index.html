Model Context Protocol · .NET 10

Database-MCP

An MCP server that exposes a SQL Server database — Azure or on-prem — to Claude. Browse schemas, tables and views, inspect structure, and query or export data as CSV/TXT. Read-only, by construction.

Read the docs Config example Claude skill

Architecture

A single .NET console application that speaks MCP over stdio. Claude launches the process; JSON-RPC flows over stdin/stdout while all logging goes to stderr so it never corrupts the protocol stream. 

Claude  <--stdio(JSON-RPC)-->  DatabaseMcp.dll

MCP tools

Eight tools cover schema navigation, structured queries, raw SQL, and bulk export.

ToolPurpose
list_schemasList user schemas (system schemas excluded)
list_tablesList tables, optionally filtered by schema, with approximate row counts
list_viewsList views, optionally filtered by schema
describe_tableColumns, primary key, foreign keys, indexes, approximate row count
describe_viewColumns and SQL definition for a view
execute_sqlRun a raw read-only SELECT/WITH statement; CSV/TXT inline, row-capped
query_dataQuery a table/view via structured columns/filters/order/limit — no raw SQL needed
export_dataStream the full result of a SELECT to a CSV/TXT file on disk

Safety model

Every code path only ever runs read-only SELECT statements against the database.

●
Guarded raw SQL.

execute_sql and export_data reject anything that isn't a single SELECT (optionally with a leading WITH CTE) — no INSERT/UPDATE/DELETE/MERGE/DDL/EXEC/multiple statements.

●
No injection surface in query_data.

Structured queries are built server-side: identifiers are validated and bracketed, filter values are always bound as parameters.

●
Context-safe by default.

Inline results are capped at a configurable row count to protect the LLM's context window; responses report whether output was truncated.

●
Streaming export, no buffering.

export_data streams directly from the SqlDataReader to disk, so extracting millions of rows never loads them fully into memory.

Read-only by design

Every tool routes through the SQL guard or the parameterized query builder — never raw concatenation.

Configurable via env vars

SQLSERVER_HOST, SQLSERVER_DATABASE, SQLSERVER_USER/PASSWORD, encryption and row-cap settings.

Azure SQL & on-prem

Falls back to Windows Integrated Security when no credentials are supplied.
